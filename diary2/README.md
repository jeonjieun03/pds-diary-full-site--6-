# 플랜두씨 다이어리 2 (SKT ALEPH 과제 7 — 인증 붙이기)

과제 6의 다이어리에 이어 붙인 것입니다. 이제 첫 화면은 로그인 화면이고,
내 계획·할 일·실행 기록·돌아보기는 로그인한 나만 볼 수 있습니다.

**과제 6(`../diary/`)과 이 폴더는 같은 Supabase 프로젝트를 쓰지만, 표(테이블)는 완전히
분리되어 있습니다.** (`plans_t07`처럼 이름 끝에 `_t07`이 붙은 표) Supabase 무료 요금제가
프로젝트를 2개까지만 허용하고 과제 8에서 새 프로젝트가 하나 더 필요해서, 과제 7을 위해
새 프로젝트를 만드는 대신 같은 프로젝트 안에 새 표만 판 것입니다. 그래서 과제 6 사이트는
이 작업과 무관하게 로그인 없이 계속 그대로 열립니다.

## 0. 과제 6과 같은 Supabase 프로젝트를 그대로 씁니다

`js/config.js`의 URL/키는 과제 6 때 쓰던 것과 동일합니다(같은 프로젝트).
이미 `diary/sql/schema.sql`을 실행해 둔 상태라는 뜻입니다. 아직이라면 그것부터 실행하세요.

## 1. 앱을 열어 먼저 회원가입을 1번 합니다

1. `npx serve .` 또는 `python3 -m http.server 8080`으로 로컬에서 엽니다.
2. 로그인 화면에서 "계정이 없으신가요? 회원가입"을 눌러, 실제 쓸 이메일/비밀번호로 가입합니다.
   - Supabase 프로젝트의 Authentication 설정에서 "Confirm email"이 켜져 있으면
     확인 메일의 링크를 눌러야 로그인이 됩니다. 꺼져 있으면 가입 즉시 로그인할 수 있습니다.
     (Authentication → Providers → Email에서 확인/변경 가능)

## 2. 인증용 표 생성 SQL 실행 (딱 1번, 가입 뒤에)

1. Supabase 프로젝트 → **SQL Editor**로 들어갑니다.
2. `sql/schema-t07.sql` 내용 전체를 붙여넣고 실행합니다.
   - `plans_t07`, `todos_t07`, `executions_t07`, `plan_revisions_t07`, `review_notes_t07` 표가
     새로 생기고, 과제 6 표(`plans` 등)에 있던 기존 자료가 **복사**되어 들어갑니다
     (원본은 그대로 남습니다).
   - "본인 것만" RLS 정책과, 남의 자료를 고치거나 지우려 하면 403을 내는 함수
     (`update_todo_secure` 등)가 만들어집니다.
   - 과제 6이 쓰는 원본 표와 정책은 이 SQL이 전혀 건드리지 않습니다.
3. 실행 후 새로고침해서, 방금 가입한 계정으로 로그인하면 과제 6 때 넣었던 자료가 그대로 보이는지 확인합니다.

## 3. 로컬/배포 확인

- 로그인하지 않고 첫 화면에 들어가면 로그인 화면만 보이고, 자료 화면(계획/할 일 등)은 보이지 않아야 합니다.
- 회원가입 → 로그인 → 로그아웃이 실제로 되는지 확인합니다.
- 같은 이메일로 가입을 다시 시도하면 "이미 가입된 이메일입니다"가 나오는지 확인합니다.
- 아이디는 맞고 비밀번호만 틀렸을 때 / 아이디 자체가 없을 때, 둘 다 "이메일 또는 비밀번호가 올바르지 않습니다"로 문구가 같은지 확인합니다.
- **과제 6 결과물 주소(`../diary/index.html`)를 새 시크릿 창에서 열어, 로그인 없이 여전히 잘 열리는지도 함께 확인합니다.**

## 4. GitHub Pages로 재배포

저장소 루트에 이미 GitHub Pages가 켜져 있다면, 이 폴더를 그대로 push하는 것만으로
`https://<아이디>.github.io/<저장소>/diary2/index.html`이 과제 7의 결과물 주소가 됩니다.
과제 6 주소(`.../diary/index.html`)는 그대로 유지됩니다.

## 5. 증거(설명서 ④, 카드 2·3·4) 모으는 법 — 브라우저 개발자도구

1. 앱을 열고 **F12**(또는 우클릭 → 검사) → **Network** 탭을 켭니다.
2. "Preserve log"를 체크해 두면 로그아웃 같은 페이지 이동에도 기록이 남습니다.
3. 아래 행동들을 하나씩 하면서, 그때마다 Network 탭에 뜨는 요청을 클릭해
   **Headers**(요청 주소·메서드)와 **Response**(응답 본문·상태 코드)를 캡처합니다.
   - 로그인 성공 / 로그아웃 후 같은 값으로 재요청
   - 계정 A로 로그인해 계정 B의 할 일을 고치기·지우기 시도
   - 로그인하지 않은 채 데이터 요청(로그아웃 상태에서 새로고침 후 Network 확인)
4. 캡처한 내용을 `SUBMISSION_T07_TEMPLATE.md`에 옮겨 적을 때,
   `Authorization: Bearer eyJhbGciOi...`처럼 토큰이 보이면 앞부분 몇 글자만 남기고 `…`로 가립니다.
   비밀번호는 절대 그대로 적지 않습니다.

## 폴더 구조 (과제 6 `diary/`와 달라진/추가된 것)

```
index.html               ← 로그인/가입 화면, 계정 바, 계정 삭제 영역 추가
js/auth.js                ← 새 파일: 가입/로그인/로그아웃/계정(자료) 삭제
js/app.js                 ← 로그인 여부에 따라 화면 전환, update/delete를 보안 함수로 교체
js/data.js                ← 모든 표 이름이 _t07 접미사 버전으로 교체, update/delete는 RPC 호출
js/config.js               ← 과제 6과 동일(같은 Supabase 프로젝트)
sql/schema-t07.sql          ← 새 파일: _t07 표 생성 + 기존 자료 복사 + RLS + 보안 함수
contracts/pds-schema-v3-auth.json  ← 새 파일: v2 대비 바뀐 스키마 계약(표 분리 이유 포함)
SUBMISSION_T07_TEMPLATE.md  ← 제출문 초안(설명서 6항목, 확인 방법, AI/내 판단, 5일 기록)
```
